# ПОС

Консольный модуль преподавательской оценки студентов

## Запуск и демонстрация

Нужен .NET SDK 10. Команды выполняются из папки с Pos.sln

    dotnet run --project src/Pos.Console

Строгий режим, в котором нужны оценки по всем критериям:

    dotnet run --project src/Pos.Console -- --complete

Проверка тестов:

    dotnet test Pos.sln

Сквозной сценарий через меню:

1. Пункт 1: добавить студента с id s1, именем Иван и фамилией Иванов
2. Пункт 3: добавить критерий exam, название Экзамен, максимум 10, вес 1
3. Пункт 3: добавить критерий project, название Проект, максимум 20, вес 3
4. Пункт 5: поставить студенту s1 по exam балл 8, по project балл 10
5. Пункт 8: получить итог студента s1, результат 5.75 из 10
6. Пункт 9: указать results.csv и получить файл с итогами
7. Пункт 5: попробовать заменить оценку по exam на 12, программа отклонит ввод и сохранит 8
8. Пункт 7: отменить оценку по project, обычный режим даст итог 2.00, строгий режим отклонит расчет

Пункты 2, 4 и 6 показывают студентов, критерии и оценки. Повторное выставление оценки исправляет ее. Дробные числа можно вводить с точкой или запятой

Данные хранятся в памяти до завершения программы. Экспорт создает CSV с колонками StudentId, FirstName, SecondName, Score, кодировкой UTF-8 и разделителем запятой. При повторном экспорте в тот же путь файл перезаписывается. Постоянное хранение и импорт не реализованы, для обязательного сквозного сценария достаточно экспорта

## Логика решений и карта DDD

Ubiquitous Language: Student соответствует студенту, Criterion критерию, Rubric рубрикатору, Evaluation оценке, TotalScoreCalculator расчету итога

| Понятие | Реализация и решение |
| --- | --- |
| Entity | Student и Criterion имеют неизменяемый id, имя не используется вместо идентификатора |
| Value Object | Evaluation хранит CriterionId и Value, не имеет собственного id и публичных сеттеров, равенство определяется обоими значениями |
| Агрегат студента | Student управляет своими оценками, по критерию хранится одна оценка, исправление заменяет объект |
| Агрегат рубрикатора | Rubric управляет набором критериев и не допускает повторяющихся id, в приложении один рубрикатор для одного курса |
| Инварианты | Непустые имена и id, конечный положительный максимум, конечный неотрицательный вес, конечный балл от нуля до максимума включительно, существующий критерий |
| Repository | IStudentRepository в Application/Ports, реализация InMemoryStudentRepository снаружи домена |
| Domain Service | TotalScoreCalculator получает студента, рубрикатор и использует выбранную стратегию расчета |

Rubric.CreateEvaluation проверяет существование критерия и границы балла. Конструктор Evaluation имеет доступ internal, поэтому Application не может создавать оценки напрямую. Сам конструктор проверяет непустой id и конечный неотрицательный балл. Internal действует на всю сборку DomainCore, а не только на Rubric

Student не вычисляет итог и не работает с файлами. Его коллекция оценок закрыта, чтение возвращает отдельный список без возможности изменения. Критерии после создания неизменяемы. Расчет дополнительно проверяет соответствие оценок переданному рубрикатору

Формула итога по шкале от 0 до 10:

    итог = 10 * сумма((балл / максимум) * вес) / сумма(весов)

Веса относительные, сумма не обязана равняться единице. Для защиты от переполнения каждый вес предварительно делится на наибольший вес, что сохраняет формулу. Критерий с нулевым весом не влияет на итог. Если критериев нет или все веса нулевые, расчет отклоняется

В обычном режиме отсутствующая оценка дает нулевой вклад. В строгом режиме требуются оценки по всем критериям, включая критерии с нулевым весом. Итог не хранится в Student и пересчитывается после исправления, отмены оценки или добавления критерия. Округление до двух знаков применяется только при выводе и экспорте

## Архитектура и зависимости

Выбрана Ports and Adapters. Каждый слой выделен в отдельный проект

| Папка | Назначение |
| --- | --- |
| src/Pos.DomainCore | Сущности, объект-значение, инварианты, рубрикатор, доменный сервис и стратегии |
| src/Pos.Application | Сценарии, фасад, порты хранения и экспорта, DTO результата |
| src/Pos.Infrastructure | Адаптер репозитория в памяти и CSV-экспорт |
| src/Pos.Console | Меню, чтение и вывод, сборка зависимостей |
| tests/Pos.Tests | Проверки домена, сценариев, ввода и экспорта |

Зависимости проектов:

    Application -> DomainCore
    Infrastructure -> Application -> DomainCore
    Console -> Application
    Console -> Infrastructure

DomainCore не зависит от файлов, консоли и внешних библиотек. Порты принадлежат Application, внешние адаптеры реализуют эти интерфейсы. Ссылка Console на Infrastructure нужна в точке сборки зависимостей

В Program используется DI-контейнер Microsoft.Extensions.DependencyInjection. Он связывает порты с адаптерами и внедряет зависимости через конструкторы. Время жизни Singleton выбрано для одной консольной сессии с общими студентами и рубрикатором. Стратегия выбирается при запуске. ConsoleApplication получает фасад, TextReader и TextWriter, поэтому ввод проверяется без ручного набора

## Паттерны

| Группа | Паттерн и место | Задача |
| --- | --- | --- |
| Порождающий | Фабрика, Rubric.CreateEvaluation | Единая точка создания оценки с проверкой критерия и границ, проверки не повторяются в консоли |
| Структурный | Facade, PosFacade | Консоль вызывает сценарии через один объект и не координирует репозиторий, рубрикатор и экспорт |
| Поведенческий | Strategy, IScoreStrategy, WeightedScoreStrategy и CompleteScoreStrategy | Доменный сервис поддерживает два правила обработки пропущенных оценок без изменения сценариев |

Фабрика реализована обычным методом рубрикатора, как допускает пример задания, без отдельной иерархии фабрик

## Тесты

DomainTests проверяет границы балла, неизвестный критерий, повторяющиеся id, некорректные параметры, равенство Value Object, исправление и отмену оценки, формулу и обе стратегии

ApplicationTests проверяет сохранение старой оценки при ошибке, отсутствие студента, повторный id, передачу актуального итога в экспорт и сквозной консольный сценарий. Заглушка экспорта запоминает переданные результаты без записи файла. StringReader и StringWriter подменяют консольные потоки

CsvExporterTests проверяет реальную запись временного файла, заголовок, кавычки, разделители и формат числа. Файл удаляется после проверки
